# Hermes: границы интеграции 1.3

**Проверено:** 2026-09-14
**Режим:** исследовательский; только синтетические технические запросы и
публичные источники. Реальные пациенты, их данные и клинические рекомендации
исключены.

## Выбор компонента и роль

- Upstream: [NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent).
- Проверенная версия: release `v2026.9.11`, commit
  `939e45c91d751fadd94dcd1b873ac3cb44846213`; пакет сообщает версию `0.21.2`.
- Лицензия upstream: MIT.
- Назначенная роль: одноразовый исследовательский CLI-процесс. Hermes не
  является клиническим валидатором, пациентским помощником, gateway или
  самостоятельным исполнителем изменений в НейроЛабе.

Hermes способен включать память, gateway, cron, MCP, навыки, файловые операции,
браузер, терминал и делегирование. Эти возможности не считаются частью данной
интеграции и не должны включаться «по умолчанию».

## Проверенный минимальный профиль

На RP5 исходники и виртуальное окружение проверялись в игнорируемом Git
каталоге `runtime/`. Для теста создан отдельный `HERMES_HOME`; локальный
ключ прокси хранится только в его env-файле с правами `0600`.

Профиль подключается только к временно поднятому loopback-only gpt2giga и
имеет следующие обязательные ограничения:

- пустой набор CLI-инструментов;
- отключены persistent memory и user profile;
- запрещены terminal, file, browser, skills, cron, delegation, code execution
  и kanban;
- `manual` approval mode; `single_query_mode: deny`;
- для terminal sandbox принудительно отключена сеть, хотя терминал также
  запрещён policy;
- нет MCP-серверов, gateway, фонового процесса и автозапуска.

Пройденный синтетический smoke-test: Hermes через gpt2giga получил ответ
`HERMES_OK`. Конфигурация была проверена программно: фактический список
разрешённых CLI-инструментов пуст, память выключена, inference endpoint —
только loopback proxy. После теста временный gpt2giga container/network
останавливаются; основной Compose-стек НейроЛаба не перезапускается.

## No-go для поискового режима

Отдельный одноразовый профиль с единственным read-only toolset `search` был
создан для проверки публичного технического поиска. Его policy была проверена:
разрешён ровно `web_search`, а terminal, file, browser, MCP, память и остальные
инструменты запрещены.

Этот режим **не допущен к использованию**. Текстовые ответы, выданные во время
двух synthetic smoke-запросов, не содержали зарегистрированного tool call:
журнал сессии показал `tool_call_count = 0`. Повтор с явным требованием ровно
одного `web_search` также не выполнил поиск; в проверяемом upstream trace
зафиксирован rate-limit ответ провайдера. Такой ответ нельзя считать ни
поиском, ни подтверждённым источником.

До отдельного go/no-go запрещено использовать Hermes для поиска, извлечения
цитат или медицинских исследований. Нельзя подменять отсутствие tool trace
правдоподобным текстом модели.

## Условия следующей проверки

1. Офлайн-contract-тест gpt2giga для OpenAI tool definitions пройден, но
   требуется живая проверка: вызов, аргументы, результат и финальный отчёт
   должны быть записаны в trace конкретного запуска Hermes.
2. Добавить ограниченный retry/backoff для 429 и проверить честный отказ без
   выдуманного результата при исчерпании лимита.
3. После восстановления доступного лимита на техническом публичном запросе
   подтвердить: один разрешённый
   `web_search` → ссылка на первоисточник → дата/ограничение/уверенность в
   финальном отчёте.
4. Только после этого создать отдельный research runbook с allowlist доменов,
   лимитами времени/стоимости и ручным стартом. Пациентский и клинический
   контуры остаются изолированными независимо от результата.
