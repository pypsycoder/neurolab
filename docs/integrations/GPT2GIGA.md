# gpt2giga: контракт интеграции 1.2

**Проверено:** 2026-09-14
**Режим:** исследовательский, только синтетические запросы; пациентские данные
и основной Compose-стек не используются.

## Выбранная версия и роль

- Upstream: [`ai-forever/gpt2giga`](https://github.com/ai-forever/gpt2giga).
- Версия: `v0.3.0`, commit `197ef424f65f5165967d325deb075988a1bed141`.
- Лицензия upstream: MIT.
- Роль: локальный FastAPI-адаптер запросов OpenAI/Anthropic/Gemini-compatible
  клиентов к GigaChat; он не является клиническим валидатором и не получает
  доступ к пациентскому контуру.

## Изолированная проверка на RP5

Проверка выполнялась из pinned исходников в локальном игнорируемом каталоге
`runtime/`, с отдельным env-файлом с правами `0600` и отдельным случайным
ключом доступа к proxy. Контейнер публиковался только на loopback-интерфейсе,
а системный CA-bundle RP5 подключался read-only. Основной Compose-проект
НейроЛаба не перезапускался.

Пройдены следующие синтетические проверки:

| Проверка | Результат |
|---|---|
| `GET /health` | `200` |
| OpenAI-compatible `GET /v1/models` | `200`, получен непустой список моделей |
| OpenAI-compatible `POST /v1/chat/completions` | `200`, ответ содержал `choices`, `usage` и ожидаемые метаданные |

После проверки отдельный контейнер и его Docker network остановлены и удалены.
Исходники и локальная конфигурация остаются в `runtime/`, который исключён из
Git; значения ключей не выводились и не попадают в репозиторий.

## Ограничения и следующий шаг

Проверены только health, model discovery и простой нестриминговый chat request.
Перед постоянным включением адаптера требуются отдельные проверки streaming,
structured output, tool calls, timeout/retry, отказа upstream и авторизации
клиента. Открывать proxy наружу, включать в пациентский контур или передавать
реальные данные запрещено.
