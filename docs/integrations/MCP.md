# MCP: test-only contracts 1.6

**Статус:** подэтапы 1.6.1–1.6.6 выполнены; внешний MCP transport не
подключён.

До появления реальных серверов НейроЛаб использует только проверяемую policy
модель трёх test-only контрактов: поиск по документации, чтение заранее
разрешённого synthetic fixture и diff ограниченного набора путей репозитория.

Каждый вызов проходит allowlist имени, точную схему параметров и ограничения
путей до того, как мог бы быть передан transport. Shell, сеть, произвольные
URL, секреты, абсолютные пути, traversal и range Git вне `HEAD` запрещены.
Ответ инструмента всегда помечается как недоверенные данные; текст из него не
может становиться инструкцией агенту.

Проверки покрывают неизвестный tool, лишние аргументы, traversal, неразрешённый
Git range и prompt injection. Никакие ключи, patient data или внешний
web-search этим подэтапом не включаются.

Локальный `stdio` test server реализован на официальном Python SDK MCP 2.2.0.
Он объявляет ровно эти три имени инструментов, применяет тот же policy gate и
возвращает исключительно synthetic-результаты. В частности, обработчики не
читают файловую систему, не запускают Git, не обращаются к сети и не читают
`.env`. Для строгого запрета неизвестных параметров сервер использует
низкоуровневый интерфейс SDK: он публикует `additionalProperties: false` и
проверяет исходный объект аргументов до dispatch. Это необходимо, потому что
высокоуровневый decorator SDK v2 по умолчанию отбрасывает неизвестные поля.

End-to-end tests запускают сервер отдельным дочерним процессом, проверяют
список инструментов и маркировку ответа как недоверенного, а также отказ по
policy для traversal и лишнего аргумента. Контролируемый отказ возвращается с
`is_error=true`, без traceback и без внутренних деталей в ответе.

Отдельно проверен единственный read-only handler для public synthetic fixture.
Он запускается только opt-in в одноразовом Docker-контейнере без сети, с
read-only root filesystem, непривилегированным пользователем, без Linux
capabilities и с `no-new-privileges`. В контейнер монтируются read-only только
исходный код сервера, зависимостное окружение и каталог `tests/fixtures/`;
`.env`, рабочий Compose-стек, Docker socket, Git metadata и данные пациентов
туда не передаются. End-to-end проверка читает один разрешённый fixture и
отклоняет traversal до чтения.

Отдельно проверен реальный `git diff` для synthetic fixture-репозитория.
Тест создаёт временный Git-репозиторий из версионируемой учебной заготовки,
делает synthetic baseline commit и одну synthetic правку, после чего монтирует
этот временный каталог в контейнер только для чтения. MCP-handler принимает
только `base=HEAD` и заранее разрешённый путь, запускает фиксированный
`/usr/bin/git` без shell, external diff, textconv, системного/глобального Git
config или интерактивных запросов. Для этой единственной точки монтирования
задано `safe.directory=/repository`; это не меняет host Git config.

В базовом ARM64 evaluation image Git отсутствует, поэтому в тест контейнера
read-only монтируются только host-бинарник Git и его `git-core` модули. Рабочая
копия НейроЛаба, `.env`, Docker socket и сеть по-прежнему не передаются. Docker
daemon RP5 подтверждённо поддерживает `pids` limit, и тест использует 64 PID;
memory limit недоступен, поэтому он не заявляется как защита. Это не production
sandbox и не доступ к произвольным файлам, Git, shell или внешним MCP-серверам.

В LangGraph добавлен отдельный deterministic synthetic trace над этими тремя
типами MCP-событий. До шага исполнения он требует ровно approved набор имён,
повторно проверяет каждый контракт и допускает результат только с
`trusted=false` и `origin=test-mcp`. Контент MCP-ответов не становится частью
управляющих условий и не попадает в итоговый отчёт. Так synthetic prompt
injection остаётся данными, а неизвестный tool или поддельный «доверенный»
результат останавливают graph до `execute`.

Этот graph не открывает MCP transport повторно и не запускает LLM, Git,
файловые операции или сеть: transport и sandbox проверяются отдельными E2E
тестами выше.

`scripts/verify_synthetic_smoke.sh` собирает эти доказательства в один
воспроизводимый RP5 pre-smoke: policy/stdio/LangGraph tests, opt-in Docker
fixture tests и компактный synthetic LangGraph report. Скрипт не читает `.env`
и не включает внешний поиск, Hermes live-search, OpenHands или рабочий
репозиторий. Поэтому он служит baseline для 1.7, но не закрывает полный
сквозной сценарий из дорожной карты.
