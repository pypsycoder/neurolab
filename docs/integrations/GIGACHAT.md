# GigaChat: контракт интеграции 1.1

**Проверено:** 2026-09-13  
**Режим:** исследовательский, только публичные и синтетические данные.

## Выбранный способ

- Язык: Python 3.11.
- SDK: официальный пакет `gigachat` 0.2.3 (зафиксирован для воспроизводимости).
- Базовый URL: `https://api.giga.chat/v1`.
- Авторизация: ключ из переменной `GIGACHAT_CREDENTIALS`; ключ не записывается
  в код, тестовые фикстуры, логи или документацию.
- TLS: проверка включена. Её отключение запрещено этим проектом.
- Scope: задаётся явно в `GIGACHAT_SCOPE`; значение должно совпадать с ключом.

SDK получает и обновляет access token сам при использовании credentials. Для
первой живой проверки запрашивается список моделей; это подтверждает
аутентификацию, доступность endpoint и разрешения, не отправляя содержательных
данных в модель.

## Режимы проверок

| Проверка | Сеть | Ключ | Назначение |
|---|---|---|---|
| Unit | Нет | Нет | Конфигурация, запрет пустого ключа, TLS и базовый URL |
| Live models | Да | Да, только в окружении | Аутентификация, endpoint, список моделей |

## Доверие TLS на RP5

На RP5 системное хранилище первоначально не содержало корень НУЦ Минцифры,
поэтому проверка TLS корректно отклоняла цепочку GigaChat. 2026-09-14 корневой
сертификат, предъявленный endpoint, был сопоставлен с загрузкой с официальной
страницы Госуслуг. SHA-256 fingerprint корня:

```text
D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31
```

В системное хранилище RP5 штатно добавлены опубликованные корневой и два
выпускающих сертификата, после чего `openssl` подтвердил цепочку и live-test
списка моделей прошёл. Скрипт `verify_gigachat_live.sh` передаёт путь к
системному CA-bundle только своему процессу через `SSL_CERT_FILE`; TLS никогда
не отключается. Он разбирает Compose-style `.env` через `python-dotenv`, а не
исполняет его как shell-код.

При смене сертификатов повторить сравнение fingerprint с официальным источником
до обновления trust store.
