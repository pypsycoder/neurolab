# ADR-0003: Поиск в исследовательском контуре только с доказательством вызова

**Статус:** accepted
**Дата:** 2026-09-14
**Владелец:** владелец проекта (пользователь)
**Пересмотр не позднее:** перед включением внешнего поиска в рабочий граф

## Контекст

НейроЛаб использует Hermes только как исследовательский компонент. В live
пробе через gpt2giga/GigaChat модель смогла вернуть текст, но не вызвала
разрешённый `web_search`; в trace зафиксирован `tool_call_count = 0`. Такой
результат не содержит проверяемого источника и может быть неподтверждённым.

Локальный mock подтвердил корректность профиля Hermes и streaming-протокола:
при реальном tool call создаётся trace и финальный отчёт. Pinned gpt2giga
также имеет контракт преобразования явного OpenAI `tool_choice` в обязательный
вызов функции GigaChat. Но Hermes передаёт инструменты без `tool_choice`, а
его режим усиления использования инструментов действует только через prompt.

## Решение

1. Ответ модели без trace обязательного поиска является отказом, а не
   исследовательским результатом.
2. Поиск в будущем LangGraph research pipeline выполняется отдельным
   программным узлом до синтеза моделью. Узел валидирует параметры, применяет
   allowlist и лимиты, сохраняет запрос, результаты, дату и идентификатор
   запуска.
3. Модель-синтезатор получает только результаты с успешно записанным trace и
   обязана явно маркировать пробелы или отказ поиска.
4. Hermes не патчится локально для скрытой передачи `tool_choice`. Если нужен
   прямой function call через gpt2giga, создаётся отдельный версионируемый
   контракт и тестируется сначала на локальном test double.

## Альтернативы и почему не выбраны

- Усилить формулировку prompt или включить `tool_use_enforcement`: это не
  меняет API-запрос и не гарантирует вызов инструмента.
- Принять текстовый ответ как результат поиска: нет воспроизводимого
  доказательства источников и времени проверки.
- Патчить Hermes runtime: изменение не будет версионируемым артефактом
  проекта и усложнит обновление upstream.

## Риски, ограничения и меры контроля

Внешний поиск остаётся недоверенным вводом: его содержимое не является
инструкцией для агента. До отдельного одобрения допускаются только публичные,
неклинические запросы; реальные пациентские данные запрещены. Любой сбой
поискового узла должен завершать запуск маркированным отказом без выдуманных
ссылок.

## Проверка и критерий отката

До включения research pipeline должен пройти сценарий: программный поиск →
trace с запросом/результатом → модельный синтез с URL, датой, ограничением и
уверенностью. Отсутствие trace, нарушение policy или результат без источника
означают no-go и отключение внешнего поиска.
